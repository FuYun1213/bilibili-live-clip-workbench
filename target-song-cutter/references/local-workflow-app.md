# 本地直播切片工作台

当用户希望在本机重复执行转写、选片文件交换、切片、字幕、封面、烧录或投稿时，使用
工作区根目录的 `切片工作台.cmd`。工作台现在有两个标签页：

- `任务与流程`：合并原主页和自动监控页，默认显示录播队列与常用任务操作；
- `切片审核台`：跨主播、跨直播场次集中列出全部待审核与退回修改的切片。

“手动项目”“监控与处理设置”“历史批处理”按需展开，最多同时打开一个；内容较多时可在面板内滚动，队列仍在下方。人物模板、热词、纠错、投稿账号、环境检查和目录入口统一放在任务页工具栏。晚到分段分析、重新调用 Codex、废弃清理在所选任务的“更多操作”菜单中。

`Ctrl+S` 按当前上下文保存：展开手动项目时保存项目，任务列表或其他面板保存自动配置，审核页保存当前切片。模式和 ASR 参数由手动项目及自动队列共用；加载手动项目会带入该项目参数，保存自动配置前应检查“监控与处理设置”。底部“刷新”同时更新手动流程和自动队列，周期刷新继续保留。

完整构成和功能清单见 [工作台功能盘点](workbench-feature-audit-20260905.md)。

界面使用微软雅黑、浅色背景和蓝色主操作按钮。右侧“执行队列”常驻显示正在执行的任务、按提交顺序等待的本地任务，以及按实际优先级排列的自动队列；每项展示操作、文件/场次标题和阶段，内容较长时可滚动。底部日志默认收起，点击“展开终端”在独立窗口查看完整记录，不占用字幕编辑区域。

投稿失败时，点击任务或“失败投稿再次投递”会复用现有成片重试发布；换源失败继续替换原 BV。它们不会重新进入转写、选片或制片队列；交付文件不完整时会提示修复。

可以多选普通发布、投稿失败续传及原 BV 换源任务，统一确认后按所选顺序分别进入发布队列。发布任务串行执行，每项在侧栏单独显示；重复点击同一任务会跳过重复请求。某一项失败、收尾回调报错或状态刷新失败，后续任务仍会继续。已有修订会保留原 BV，普通投稿继续沿用成功回执去重。单任务换源完成通过状态栏和日志通知，不会用弹窗挡住接下来的任务。

待执行的本地命令保存在本次工作台进程内；自动队列保存在原队列文件中。退出工作台前应等待本地发布队列完成，已有退出确认会提示仍在运行或等待的任务。

## 审核界面与人工重做理由

审核页右侧分为“字幕编辑”“投稿信息”“审核意见”，默认显示字幕编辑；审核决定按钮固定在底部。切片列表与视频预览按窗口高度分配空间，投稿设置和审核意见可独立滚动。字幕列表支持水平、垂直滚动，点击“全部字幕”清空检索条件；选中后在下方编辑文字、角色及起止时间。微调时间、角色映射和词库等功能位于“字幕工具”，播放及时间轴扩展操作位于对应菜单。

“查看重做理由”会打开“审核意见”，显示已有详细建议和补充备注。可以补充理由并单独保存，不改变审核决定；Ctrl+S 也保存理由。新标记“人工重做”前必须填写理由或审核建议。没有旧理由时明确显示未填写，不自动编造。

Windows 启动时在创建窗口前声明系统 DPI 感知，Tk按屏幕真实 DPI 绘制；正文字体统一为微软雅黑，日志保留等宽字体。真实布局回归覆盖100%及150%文字缩放和1280×760、1440×900、1720×980窗口。

B站返回上传限流601或提交稿件限流137022时，发布程序保存跨任务共享的递增冷却：连续受限时等待10、20、40分钟，之后每次最多60分钟；实际投稿成功后重置。每项最多尝试3次，切换任务或重新打开工作台不会清除仍在生效的等待。失败详情显示平台错误，已成功稿件仍按回执跳过。这是本地重试间隔，不保证平台届时解除限制；文件传输成功也不代表稿件提交成功。

## 手动项目

在“手动项目”中选择录播、主播 profile 和项目目录；在“监控与处理设置”中选择普通切片、歌切或“混合切片（普通+歌切）”及 ASR 参数。混合模式的完整契约见 [mixed-workflow-template.md](mixed-workflow-template.md)。录播文件自身同时提供画面和
声音，不再接受独立音轨覆盖。选择录播时，
工作台自动寻找同目录、同文件名且非空的 Bilibili XML，找到后立即填入“弹幕 XML”并显示
绑定状态；用户仍可手动更换。没有可用同名 XML 或前缀候选不唯一时保持未绑定，不猜测。
每个项目用 `workflow-project.json` 保存状态。更换源、主播或模式会使后续阶段失效，但不会
删除旧运行目录。

### 人物与字幕模板

“任务与流程”顶部统一提供“人物与字幕模板”入口。用户可手动新增人物，并编辑人物代号、显示名、
直播间房间号、字幕主题色、字体、普通字幕字号和电台字幕字号。用户也可点“移除当前人物”：
程序先检查当前手动项目和自动队列，仍有未完成任务引用时阻止；确认后仅把 profile 标记为 archived、
隐藏于识别和下拉框并关闭投稿，不删除录播、工程、字幕或成片。归档房间不会再次自动添加；以后用
相同人物代号保存会恢复该 profile。保存后写入 assets/creator-profiles.json；下一次流程 1/3 使用新
热词和字幕样式。封面主题色、字幕正文色和字幕描边色现在相互独立：所有人物使用不同的高区分度
正文色，字幕统一使用近黑色粗描边；活跃人物的正文色重复或 RGB 距离小于 55 时，人物配置校验会
阻止保存/投稿，避免多人字幕再次撞色。电台布局仍用封面主题色绘制右侧信息区和分隔线，但正文与
描边沿用同一套安全字幕色。字体必须
是本机 FFmpeg/libass 能加载的字体。

哎小呜的预置人物代号是 aixiaowu，主题色固定为 #F9A699。由于尚未提供她的空间、直播间、
固定简介、投稿 Tag 和合集，upload.enabled 保持 false，Flow 5 会明确阻止误投稿。

自动监控优先按录播文件名中的房间号匹配现有人物。遇到新的数字房间号时，默认创建稳定的
room_<房间号> 草稿；若即时父目录形如“房间号-人物名”，自动提取人物名，否则显示为
“新主播（房间号）”。草稿会生成唯一主题色并继续流程 0–4，但不猜测 VirtuaReal 归属、简介、
Tag 或合集，也不允许上传。没有房间号或匹配结果冲突时才停在 needs_creator。
### 自动流程 0：素材预检与断连合并

自动队列在转写之前递归扫描稳定的 `.flv` 和 `.mp4`。每个分段单独运行 ffprobe：
零字节、无可用时长或不可解码的分段不会终止整场任务，也不会被移动或删除；程序把路径、
签名、格式和失败原因写入队列状态，只有文件签名变化后才重新检查。其余有效分段再按同场
证据归并，生成连续母版、统一 XML 时间轴和 `continuity/preflight-report.json`。报告列出
接受、合并、直通和跳过的全部分段。只有流程 0 成功后才进入流程 1。

### 流程 1：后台转写

普通切片运行整场中文转写并过滤礼物感谢；歌切运行中日英多语转写；混合模式只运行一次中日英多语转写，再从同一份结果过滤礼物感谢。有 XML 时，同时分析
弹幕流速、重复弹幕、关键词和 SC。全程写项目日志，可取消和恢复。

### 流程 2：Prompt 与选片 JSON

生成：

- `selection/selection-prompt.md`；
- `selection/selection-context.csv`；
- 可用的弹幕热点、SC 和 engagement 摘要；
- `selection/selection-template.json`。

普通或歌切模式的业务 JSON 是数组；混合模式顶层是“普通切片”和“歌切”两个数组。所有数组内的每项都只有“标题”“副标题”“时间戳”：

```json
[
  {
    "标题": "明确主语、动作和结果的完整标题",
    "副标题": "主文案｜副文案",
    "时间戳": [
      {"开始": "00:12:34.500", "结束": "00:13:20.000"}
    ]
  }
]
```

多个时间段的数组顺序就是成片顺序，支持非连续剪辑和倒叙冷开场。普通切片总时长加末尾
余量必须为 30–300 秒。普通切片副标题分为上下两个输入区，每区 3–22 个有效字，可在区内手动换一行；歌切副标题只在上区填写完整歌名。

### 流程 3：切片、ASS 与封面

程序验证时间段，使用录播自身的声音与画面导出无字幕片段，再对实际成片运行 clip-local
Whisper/VAD，写同名 ASS、`titles-and-covers.csv` 和同目录封面。每次运行创建新批次，
不覆盖旧审核素材。混合模式共享一次导出，但按每条 content_type 分别生成叙事 ASS／VAD QA 或歌切歌词审核表。源文件名含电台／radio，或 ffprobe 按旋转信息换算后显示竖屏/方屏时，Flow 3 自动生成唯一的 1920×1080 左原画／右字幕审核稿；普通横屏保持标准版式。人物 Profile 中的字体、电台字号和主题色直接进入该稿；Flow 4 从保留的无字幕电台母版重新烧录，避免二次叠字。

### 全局审核台与内置时间轴

审核页默认扫描 `workflow-projects` 下所有 `review-decisions.json`，只把 `pending` 和 `revise`
集中列为全局待办，并显示主播、直播场次、片段、状态与标题；不再局限于当前批次的 001–004。
通过后该条从全局待办移除并保留生成物；不通过后只把该条生成的 MP4、ASS、封面和审核缓存移入回收站，原始录播不删除。
需要查看历史结果时仍可载入单个审核目录。

点击审核表中的“直播场次”列，或点右侧“整场录播预览 / 新建切片”，可打开完整录播与整场
转写。窗口支持检索转写、双击跳转、用当前播放位置标记开始和结束，并由人工填写标题、副标题和
参与嘉宾后追加一条选片；随后重新生成审核素材，旧审核批次继续保留。

左侧直接使用本机 VLC 的 `libvlc.dll` 内嵌播放视频，并从当前 MP4 音轨异步生成可点击、可拖动
的波形。红线是播放头，阴影是当前字幕区间。审核页未聚焦文字输入框时，`←` 把播放头写入
当前字幕开始，`→` 写入结束；按钮提供同样操作。修改文字、时间或说话人后自动写回 ASS，`Ctrl+S` 也可立即保存当前审核修改。字幕强制单行，删除 `\N`，连续英文单词、缩写和数字不得从中间断开。

字幕列表上方可按文字、说话人或时间检索，并用“下一个”逐条定位。参与嘉宾可从人物配置中
多选，也可追加未配置的临时嘉宾；说话人下拉框只提供本场主播、已选嘉宾和字幕中已经存在的名字。
米汀Nagisa、克罗雅Kloa、雾深Girimi 已提供独立描边色的嘉宾字幕配置。新增或启用纠错词后，
工作台会把所有启用规则重新应用到当前切片的全部字幕行，并同步无损母版对应的 ASS，不再只改当前行。


“当前字幕行”的“说话人对应角色…”可列出当前切片全部说话人、字幕数量和台词示例，
为每组选择任意已启用的人物模板。点击“应用到对应说话人的全部字幕”后，同组的名称和
字幕样式一次写入 ASS，重开切片后仍保留；文字、起止时间和上下文标记不变，Ctrl+Z 可撤销。
没有说话人名称的字幕按已有样式分组；若同组包含不同声音，先用单行“说话人”区分。

审核预览使用短 MP4 的局部时间，剪辑应用始终使用整场源视频的时间。应用后保存新的
成片到原片映射，防止重开时重新套用旧切点。未应用草稿的字幕留在工作副本，随视频一起
应用后再写入成片；播放器关闭自动加载旁置 ASS，避免旧字幕与编辑器字幕同时出现。
导出保留 MP4 的零起点，不为编码缓冲把音视频整体向后平移。

波形区现在是双轨简易剪辑器：上轨是视频保留片段与波形，下轨会把每条 ASS 字幕显示为独立可选块。`空格`
播放/暂停；普通滚轮横向移动时间轴，按住 `Ctrl` 再滚轮才以鼠标位置为中心缩放；`C` 在播放头切开，
点击上轨片段后按 `Delete` 做波纹删除，删除后前后片段自动粘合，受影响字幕同步移除、裁短或
整体前移；`Ctrl+Z` 撤回最近一次切开、删除或字幕修改。点选下轨字幕块后，拖中间可在时间轴上整体移动
字幕且保持原时长；拖左右白色把手可分别修改开始和结束。松手后立即写回 ASS。为避免在文字输入时误删，
`Delete` 只在上轨时间轴获得焦点时生效。

切开和删除先保存在 `.timeline-edits` 非破坏性草稿中，重启工作台后仍会恢复；点击“应用剪辑稿”
才用 FFmpeg 生成新审核 MP4，并在 `.timeline-edits/sources` 保存剪辑前视频。点击“放弃未应用剪辑”
可恢复剪辑前字幕。存在未应用草稿时流程 4 会明确阻止烧录，防止烧录旧画面和新字幕的混合状态。

应用剪辑时，保留范围完全落在现有切片内的删减会先映射到切片时间轴并直接读取短视频；延伸到片外时才读取整场源视频。界面显示生成用时。视频、字幕和源时间映射一起提交，失败时保留原片和剪辑草稿并恢复操作按钮。后台完成回调出错不会停止后续消息处理，错误保存在 `logs/workbench-callback-errors.log`。

审核台直接编辑标题、副标题和投稿 Tag；Tag 占用原备注位置，人工可填写 1–5 个具体搜索词。`Ctrl+S` 保存当前标题、副标题、Tag 和字幕修改。每批的 `review-decisions.json` 保存 `pending`、`approved`、`revise`、`skipped`：流程 4 只接收已通过条目，`revise` 阻断，`skipped` 不烧录、不投稿。

勾选“显示审核通过历史”时，状态列明确显示“审核通过”，选中后详情区同时显示绿色“审核状态：审核通过”。同一项目重跑 Flow 3 留下的旧审核目录不会再次进入全局池；优先采用 `active_review_dir`，旧状态缺失该字段时按当前 Flow 3 输出或最新决定文件选取唯一审核批次。

误点“写入为通过”后可点击“回退上次通过”：工作台恢复通过前的审核状态与备注，将切片重新放回列表并选中，标题、简介、字幕等已保存修改不会丢失。最后一条决定后保留 8 秒撤销时间，再检查是否进入烧录/投稿；后台已开始、已经烧录待投稿或已经发布时禁止直接回退，须从已通过历史走修订与替换流程。

审核台会提前显示最终投稿简介：单条切片导语在前，人物 Profile 中的通用投稿简介模板在后；实际
投稿仍使用同一拼接函数并自动防止重复。副标题使用两行高的多行编辑框，方便查看和修改长文案；
普通切片可手动换行，未手动换行时封面渲染器仍会自动排版。

封面制作工具会带入审核页当前的主副文案，支持缩放和滚动；窄窗口中预览自动移至表单下方，底部生成按钮始终可见。

选片输入仅保留起止时间、完整正文和说话人信息，去除语言字段、置信度及模型内部数据。自动选片会把所选范围内的全部材料直接传入同一次模型调用，并保存 `selection-input-audit.json` 的输入摘要；不依赖终端输出长 CSV，避免正文被截断。材料缺失或超出输入预算进入待修正，不能当作无候选。空结果会说明本次检查范围；普通模式录播不足 30 秒时明确提示素材不足。

### 流程 4：烧录与审计

手动项目要求用户确认边界、文字、时间、说话人、歌词和封面。普通切片从无字幕母版烧录一次；
歌切先通过现场歌词轴门禁，再生成原生 ASS。每次烧录前会用最新保存的主副文案和封面设置，强制重生成所选切片的封面，再把这些新封面复制到最终交付；生成失败则停止烧录，不沿用旧图。手动开始烧录时也会先保存当前项目正在编辑的文案。媒体、字幕、时长、解码和最终交付审计失败会
停止。

### 流程 5：预览与投稿

投稿预览前会自动修复当前交付包的全部封面，已烧录但等待投稿的历史任务也会执行。优先使用审核目录中的最新文案、封面设置和审核视频；审核素材已不存在时回退到交付包。沿用人物最新模板，不重新烧录视频。普通投稿和已发布稿件换源都使用这一步。全部新封面生成并校验成功后才替换交付图片、生成新的预览摘要；失败会停止，并使旧预览失效，不能继续用旧封面投稿。

换源重试会按封面图片内容校验已上传的封面缓存。封面更新时重新上传图片，已上传的视频继续复用；相同视频和相同封面已有成功回执时仍跳过，避免重复换源。

先预览视频、标题、封面、分区、版权、来源、简介、Tag 和合集。新人物尚无合集 ID 时，预览只显示
按中文名推导的 `XX切片`／`XX歌` 目标，不读取 Cookie、不联网。用户在“确认 / 取消”对话框确认后，
程序先精确查找同名合集；没有时上传本批封面作为合集封面并创建，回读正整数 season_id/section_id 后
写回人物 profile。新人物始终先准备 `XX切片`，即使第一批只有歌切；存在歌切时再准备 `XX歌`。
随后才执行投稿和合集加入回读。文件或投稿字段改变会使预览摘要失效；内部确认令牌仍由程序自动生成并
校验，用户不再手输。

Flow 5 对本机使用同一共享状态的投稿和换源任务使用操作系统文件锁，覆盖查重、上传及回执写入，避免跨进程同时提交；等待进程退出后锁自动释放。界面显示“等待前一条投稿完成”，获得执行机会后再读取最新冷却时间。

Flow 5 另有本地节流规则：逐条投稿并完成回执，每成功 5 条后记录 10 分钟冷却截止时间；存在第 6 条或后续任务时显示剩余时间，等待结束后自动继续。冷却状态保存在本机私有目录，不随单个项目清理；程序中断、工作台重启或切换到下一批任务时会读取同一状态继续等待。已有成功回执或回读到同标题稿件只做跳过与合集确认，不重复占用新的投稿额度。

## 新录播自动监控

任务页默认监控 `录播` 文件夹，输出到 `workflow-projects/自动队列`。工作台打开后会在未勾选
回填、自动烧录和自动投稿时自动启动安全监控；涉及这些高影响选项时仍需手动确认。首次启动默认把已有
媒体记为基线，只处理以后新增或继续写入后变稳定的素材。只有用户明确勾选并再次确认时，
才回填处理已有素材。新数字房间号默认自动建立禁止投稿的人物草稿，工作台每次刷新队列时同步刷新人物下拉框。

“文件稳定秒数”只判断单个文件何时可运行 ffprobe；“断线重连观察秒数”判断整场直播是否真的结束，默认 900 秒。同一录播子目录、房间号和录制日期下只要有任一媒体文件继续增长或出现新分段，观察倒计时就从最后写入时刻重新开始；新分段即使尚未稳定或标题发生变化也会阻止旧分段提前进入流程 0。工作台状态栏显示“断线观察”数量，详细状态包含剩余秒数。观察期间不探测活动分段、不转写，也不调用 Codex。

“监控与处理设置”中的“每天定时批量烧录并上传”默认启用，本机时间默认 17:00，可填写任意有效
HH:MM。该时间只给自动监控拥有的流程 4–5 开闸：开闸前流程 0–3 仍可生成审核素材，
已审核任务停在等待烧录或等待投稿；到点后队列逐批继续。定时设置不会授予权限，当前监控仍须
分别取得本次烧录和本次上传确认；关闭监控后授权失效。手动点击“烧录并上传”属于当次明确操作，
不受定时门槛限制。此设置依赖工作台监控进程处于运行状态，不会创建操作系统后台计划任务。

### 审核通过后的上传、清理与失败重试

自动任务按以下顺序操作：

1. 审核台逐条选择“通过”“不通过”或“人工重做”；标题、副标题和投稿 Tag 可在决定前直接编辑。
2. 最后一条完成决定后，工作台自动汇总全部通过稿并弹出“确认 / 取消”。确认后一次连续执行烧录、审计、预览和公开投稿；取消后保持待投稿，可在任务页点“烧录并上传”再次确认。
3. 同批最多两条并行烧录以兼顾速度和电脑响应；上传逐条执行，条目间冷却。每条成功后写 `publish-receipts.json`，再次运行会按回执和 B 站同标题回读跳过已成功稿件。
4. 只有投稿、合集加入和 B 站回读全部成功，任务才标为“已发布待清理”。上传成功后不自动弹出清理确认，也不阻塞后续任务；源文件默认保留。需要释放空间时，在任务列表手动选择一个或多个已发布任务清理，清理对话框显示主播、场次时间和标题，不要求输入任务 ID。

清理只接受任务清单里的精确路径：普通自动任务为该场录播分段、各分段绑定的弹幕/SC XML，以及该任务在自动输出目录下的项目文件夹。已登记的独立审核发布包还需核对批次注册、原始清单、发布清单和包内来源，全部一致才接受精确的单片生成目录；这类任务只清理审核发布包，保留原录播、原项目和批次记录。共享包、来源不明目录、符号链接及目录联接不接受清理；批量操作先验证整批，再开始执行。监控根目录、自动输出根目录、其他场次、Cookie 和全局配置不会进入清理清单。清理成功后任务自动从进度表隐藏，但中央队列仍保留删除审计记录；若某个文件被占用，任务显示“清理未完成”，关闭占用程序后可以再次点击相应清理按钮。

Flow 2/Codex 生成失败时，选中任务，在“更多操作”中点“重新调用 Codex”。工作台会先说明模型和推理强度以及新增 token 用量；确认后归档旧的 `selection.codex*.json`，保留 Flow 1 整场转写，仅重置 Flow 2–5，并明确发起一次新调用。程序不会在失败后自行无限重试。
### 按时间段批量处理已有素材

展开“历史批处理”，填写“批量开始（本机，含）”“批量结束（本机，含）”，点击“批量处理这个时间段”。时间接受
`YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM[:SS]`；只写日期时，结束日期包含当天全天。程序：

1. 扫描时间范围相交的稳定完整场次，而不是简单按文件修改时间挑单个分段；
2. 运行流程 0：逐段校验 FLV/MP4，记录并跳过坏分段，把可用断点及其同名非空 XML 合成连续母版和统一弹幕/SC 时间轴；
3. 复用已经存在的场次任务 ID，避免重复建项目；
4. 首次批处理时把其他现有文件设为基线，防止随后启动 watcher 时把整个历史目录误当新素材；
5. 顺序执行所选场次的流程 0–3，并按本次烧录、投稿授权决定是否继续流程 4–5。

仍在写入或尚未超过断线重连观察时间的场次会被跳过并计数；同直播间新分段会重置倒计时。批量投稿每次都使用“确认 / 取消”对话框授权，任务进程结束即失效。

### 同一场直播断点连续

录播姬断线可能产生多个 FLV 或 MP4，以及各自的 XML。自动队列按以下证据归并同一场直播：

1. 同一主播子目录；
2. 文件名中的房间号；
3. 同一直播日期和标题；
4. 前一段结束到后一段开始不超过配置的连续窗口。

同直播间最后一次媒体写入超过“断线重连观察秒数”（默认 900 秒），并且待处理分段已稳定后才开始处理。倒计时按目录、房间号和录制日期监控全部媒体活动，不会漏掉正在增长、尚未稳定或标题刚变化的重连分段。流程 0 会先逐段校验，并用有效分段生成：

- `continuity/continuous-source.mkv`：按开始时间排序的连续母版；
- `continuity/continuous.xml`：按拼接后累计时长偏移的统一弹幕、SC、礼物和舰长时间轴；
- `continuity/segments.json`：有效源路径、签名、原始开始时间、时长和 XML 对应关系；
- `continuity/preflight-report.json`：接受格式、合并方式、有效时长及所有被跳过坏分段的原因。

优先无损流复制；不兼容时自动退回一次标准化转码。输出时长低于分段总时长 90% 会停止。
已经发布的场次若后来出现新分段，会进入 `late_segment`，不得自动重发。

### 自动流程 0–3

队列为每场直播创建独立工作台项目，先运行流程 0，再自动运行流程 1。完成后调用独立 Codex CLI 的
非交互模式执行流程 2：

```text
codex exec --ephemeral --sandbox read-only --skip-git-repo-check \
  --output-schema selection-schema.json -o selection.codex.json "选片任务"
```

这是官方支持的脚本化调用方式。程序先用热点、SC 和关键词定位候选邻域，但每个邻域实际向前扩
120 秒、向后扩 180 秒，重叠区间合并后再计算一小时上下文预算；Codex 只读 `selection` 文件夹中的
Prompt、这份有真实前后文的 selection-context.csv 和 engagement/SC 文件。Prompt 先要求淘汰只有
话题、普通问答、粉丝滤镜、孤立怪话、重复信息或没有落点的弱素材，再按语义话题岛向前寻找起因、
向后寻找升级和真正收尾；核心不足 90 秒时仍必须检查完整的前 120／后 180 秒，但只把同一因果链
写入时间戳，不机械填时长，也不从另一话题拼结果。只有能从原句复述为“起因 → 变化／升级 → 结果
或反应”的 4–5 分素材才输出。

普通／歌切模式因结构化输出要求使用“选片”对象包裹数组，程序随即拆包；混合模式一次返回“普通
切片”和“歌切”两个数组。程序会再运行时间、逐类型标题／封面文案和 Tag 门禁；本场只调用一次
Codex，失败时保存无效结果并暂停，不自动消耗第二次调用。门禁版本升级或用户重试时，程序先在
当前目录及 manual-retries 归档中重新验证旧 JSON；新规则已经能接受时直接恢复，不发起模型调用。
空数组表示没有合格片段，任务记为 `no_candidates`，不会为了凑数进入流程 3。

自动选片不依赖人工把 Prompt 复制到 Codex 对话，但仍需要已经安装并登录的独立 Codex CLI。
Microsoft Store 桌面应用入口不能当作后台 CLI。CLI 缺失或不可执行时，任务停在
`needs_codex`，每五分钟低频重试，不会继续切片或投稿。安装与登录应遵循
[Codex CLI 官方说明](https://learn.chatgpt.com/docs/codex/cli)。

选片 JSON 通过后，队列自动执行流程 3，生成无字幕片段、成片轴 ASS、封面和审核表。

### 自动烧录门禁

无人值守烧录是每次启动监控时的显式选项，不是永久许可。

- 普通切片：只有 `subtitle-vad-qa.csv` 没有未处理的 `needs_review=yes`，且每个 MP4 都有
  同名 ASS 时才继续；后续原有字幕、媒体和最终交付审计仍全部执行。
- 混合切片：普通片段检查各自的 VAD QA，歌切片段检查同批歌词校对；任一分支有未解决项都暂停，不会让一类的通过状态掩盖另一类。
- 歌切：程序不把原始 ASR 当正确歌词。`lyric-corrections.csv` 仍有空白或未审核行时暂停；
  用户修正并保存后，文件签名变化会唤醒队列继续。
- 任意 QA 需要判断时，任务进入 `awaiting_delivery_review`。队列不会每轮重复烧录，只有
  审核文件发生变化或下次获得新的运行授权时才恢复。

批准记录保留 `source=human` 或 `source=automated-qa`，并继续绑定当前内容摘要。

### 自动投稿授权

自动投稿也只对当前监控进程有效。勾选后必须在“确认 / 取消”对话框中明确确认。程序关闭或监控停止后授权失效。每条视频仍先运行本地预览，程序在内部按当前交付数量生成并校验精确确认令牌；
只有预览摘要未失效才执行 biliup。候选总数不设固定上限；每条都必须取得 BV/aid、加入正确合集并回读成功，失败后按回执续传。
未授权时任务停在 ready_to_publish，只保留交付和预览。人物草稿即使本次获得上传授权，也会在 Flow 5 被 upload.enabled=false 拦截，必须先人工补全并启用投稿配置。

Cookie 仍只位于 `%LOCALAPPDATA%` 的私有文件，不进入项目、OneDrive、日志、Prompt 或聊天。

## 实时工作进度

工作台不要求用户从日志猜当前进度：

- 手动项目保存后，底部状态栏列出每个流程的未开始、进行中、已完成或失败；未使用手动项目时显示“就绪”或后台任务数；
- 任务页按直播场次显示直播时间、主播、标题、当前工作、百分比、状态和最近说明；说明按实际列宽和字体自动换行，完整保留文字，不限制为两行，也不添加省略号；
- 表格每 1.5 秒从原子状态文件刷新；数据和列宽不变时不重建表格，更新或重排时保留阅读位置、焦点和任务选择；程序重启后继续显示已有进度；
- 拖动说明列的分隔线或缩放窗口时自动重新排版；同一说明的所有显示行均对应同一个任务，拖动及 Ctrl 多选仍按任务计算；
- 蓝色表示处理中，黄色表示排队或等待人工/授权，红色表示失败，绿色表示完成；
- 选中任务后点击“打开选中任务审核素材”，或双击任务行，优先直达当前审核目录；尚未生成审核素材时打开项目目录。

自动进度是可恢复阶段进度，不伪造模型、ASR 或 FFmpeg 内部帧级百分比。关键节点为：
流程 0 完成 10%、流程 1 完成 25%、流程 2 完成 45%、流程 3 完成 65%、流程 4 完成 82%；
投稿预览完成但等待授权为 90%，投稿及合集回读完成为 100%。无合格片段是正常终态，
显示 100%；失败保留失败前的最后进度和说明，不倒退到 0%。

## 队列状态与恢复

常见状态：

```text
queued -> running -> no_candidates
                  -> awaiting_delivery_review -> ready_to_publish -> published
                  -> needs_codex
                  -> failed
                  -> late_segment
```

状态、素材签名、时长缓存、无效分段记录和任务恢复点写入自动输出目录的 `workflow-auto-state.json`。锁文件
防止同时启动两个 watcher；进程被强制结束后，下一次会识别并清理失效 PID 锁。普通失败最多
自动退避重试三次，避免错误循环消耗模型或重复媒体工作。

## 字幕切点预检

选片审核通过前，流程 2 会生成最终剪辑计划（包括内部拼接点和礼物剔除），
检查每个切点的权威字幕时间；整句时间不足时，只对相关字幕做本地声学字词对齐。
流程 3 复用同一份已检查的计划，素材、字幕或选片变化后会重新预检。

无法可靠对齐时，任务显示 `awaiting_selection_review` / “字幕时间待修复”，
说明具体原因并保留选片结果；此类问题不会按普通失败再次自动重试三次。
模型安装方式见 `setup.md` 的 Local subtitle timing 一节。

## 命令行入口

桌面应用调用同一脚本，也可以手动诊断：

python target-song-cutter/scripts/workflow_auto.py --config workflow-auto.json doctor
python target-song-cutter/scripts/workflow_auto.py --config workflow-auto.json status
python target-song-cutter/scripts/workflow_auto.py --config workflow-auto.json scan
python target-song-cutter/scripts/workflow_auto.py --config workflow-auto.json batch --start "2026-08-01" --end "2026-08-07 23:59"
