# 芙娅之魂回火测试｜游戏联动选片专属规则

本场是游戏联动。以下规则覆盖通用 Prompt 中“普通叙事切片”的选片优先级，但不改变证据、边界、多人识别、固定标签和 JSON 输出契约。

## 以游戏事件链为最小单位

不要把连续游戏进程当成一个故事。每条只保留一件能独立复述的游戏事件，优先寻找“目标／规则／计划 → 尝试或操作 → 局势变化 → 结果与反应”的闭环。陌生观众不需要看过整场，也应在开头 3–8 秒知道主播正要做什么、担心什么或和队友争论什么。

优先选择：

- 初次发现机制、误解机制或学会机制，并立刻产生明确后果；
- 自信制定战术、配装或分工，随后成功兑现或快速翻车；
- 失误、死亡、团灭、地形杀、误触机关、资源浪费等事故，且有完整铺垫和后续反应；
- Boss、精英怪、解谜、任务或限时挑战中，局势出现清晰变化；
- 队友配合、误会、抢资源、互相提醒、甩锅或救场，且笑点由实际游戏行为触发；
- 游戏 AI、物理、Bug 或随机事件造成的意外展开；
- 对具体系统、角色、关卡、操作或设计的鲜明评价，且评价由本段实际体验引出并有明确观点；
- 同一次行动中的递进笑点，例如第一次失误 → 修正计划 → 以另一种方式再次失败。

以下内容不单独成片：

- 赶路、刷怪、读菜单、加载、整理背包、重复尝试、普通胜负和没有升级的流水进度；
- 只有“好难、赢了、死了、救命、好可爱”等情绪，没有可说明的对象、动作和后果；
- 单独尖叫、笑声、口癖或卖萌，但观众无法从本段知道发生了什么；
- 大段世界观或剧情复述，却没有新判断、冲突、反应或落点；
- 与当前游戏行为无关的队友闲聊、礼物感谢、弹幕问答和临时岔题；
- 仅凭标题、弹幕或热度猜测画面中发生的事，或杜撰转写没有证据的角色名、机制名和剧情。

## 游戏边界与多人联动

开头从目标、规则、队友指令、主播计划或第一次关键操作前的必要一句开始；结尾保留结果、反应、复盘或明确的下一步决定后立即结束。菜单、赶路、等待和无关重试应删除。同一条可用多个时间段绕开空白，但只能属于同一次行动链；不得把彼此无关的多次失败拼成虚假的递进。

联动片段必须让人听清“谁做了什么、谁对此作出反应”。只有选中范围内确实有可听台词的人才写入参与者；房间标题、组队名单、立绘、弹幕点名和未能辨认的声音都不能替代说话人证据。

## 游戏标题、副标题与 Tag

标题优先写明具体人物、游戏动作或机制以及真实后果，例如“刚定好分工就误触机关”“研究半天配装，进战斗才发现装反了”“队友提醒别碰机关，下一秒直接团灭”“第一次躲过 Boss 大招，却输给了地形”。这些只是结构示例，不能照抄，也不能写入素材中没有的事实。

禁止用“游戏高能、爆笑实况、精彩操作、节目效果、当场破防”等空话代替事件。副标题按通用副标题专节写作：上下区合读要有具体对象或事件锚点，可以用原话、短促接话或贴切的比喻，不必每区都是完整事实句；语言可以俏皮，但不得编造操作、队友台词和游戏后果。

五个片段专属 Tag 优先覆盖有证据的游戏实体、角色／Boss／关卡、具体机制、操作／关系和事件类型；只有确实有帮助时才使用“游戏切片”。活动名和主播完整 ID 会由程序作为固定投稿 Tag 自动加入，不得在五个片段专属 Tag 中重复。
