# 竖屏直播（电台）横屏模板与发布文案

## 识别与唯一交付路径

在生成用户可见文件之前先分类。ffprobe 按视频旋转标记换算显示方向后，只要高度大于或等于宽度（竖屏或方屏），就默认视为电台版式；普通横屏不自动改版。文件名含“电台”或“radio”时无条件强制使用本模板。画面虽为横屏但属于缺少有效动态构图的电台回，可在文件名加“电台”明确路由。不得把普通竖屏切片当成可交付版本。

- 普通竖屏裁切、原始比例 MP4 和未烧字幕的横屏布局只允许留在内部工作目录。
- 用户可见的审阅目录只放电台模板成片和同名可编辑 ASS，不再并列 `source-XX/clips` 普通版或可被误认为终稿的 `vertical-layout` 备选目录。
- 右侧字幕区是电台画面构图的一部分；空白右栏的 MP4 属于中间态，不能审阅或交付。

## 版式

输出 1920×1080：

- 将原视频等比缩放至高 1080，置于左侧 1/3，保持完整画面，不裁切、不拉伸。
- 将同源画面铺满背景并重度模糊、降低饱和度，再叠加以角色色调和白色混合的浅色遮罩。
- 在右侧留出带内边距的模糊信息区；用角色色的低透明度细线分隔左右区域。
- 将普通叙事字幕置于右侧信息区中央，使用人物 Profile 的 dialogue_font、粗体、白色填充、role_color 描边和轻阴影。
- 默认 radio_subtitle_size 为 65；用户可在“人物与字幕模板”中为该人物设置 24–160 的已审字号。每场只读取 Profile 的绝对值，不按百分比累加。
- 输出已经烧录字幕的审阅 MP4，并在同一目录保留同名可编辑 ASS。烧录版仍是内容审阅稿，不代表用户已经批准终稿。

先生成模板画面和同名 ASS，再烧录：

```powershell
python scripts/render_vertical_radio_layout.py `
  --input-dir "review/clips" `
  --output-dir "work/radio-layout" `
  --ffmpeg "tools/ffmpeg/ffmpeg.exe" `
  --color "#8eb056" `
  --speaker "小松绿" `
  --style-name "ViridisRadio" `
  --font "Microsoft YaHei" `
  --font-size 65

python scripts/burn_ass_subtitles.py `
  --clips "work/radio-layout" `
  --ass "work/radio-layout" `
  --output "review-radio/clips" `
  --ffmpeg "tools/ffmpeg/ffmpeg.exe" `
  --fontsdir "assets/fonts/smiley-sans-v2.0.1"
```

把 `work/radio-layout` 中的同名 ASS 复制到 `review-radio/clips`，确保每个烧录 MP4 旁边都有可编辑 ASS。在交付前抽查每条视频第一句、片中和片尾三处：确认字幕已经实际显示、字体/字号/主题色与人物 Profile 一致、左侧原画完整、右侧字幕没有越界、描边与背景有足够对比，音画时长未因重排版而截断。

## Title 与封面组合

每条竖屏直播（电台）切片默认提供三套完整组合，而不是两个只有同义词差别的标题：

```text
bundle_id
title
cover_mode
cover_text_primary
cover_text_secondary
evidence_frame
```

三套分别使用：

1. `quote-collision`：原话或金句在前，紧接真实后果；
2. `narrative-reversal`：人设、保证或计划在前，现实打脸或情绪反转在后；
3. `relationship-challenge`：人物关系、SC/弹幕引导、争议点评、比赛或误解作为钩子。

### title：频道标签前置，正文完整叙事

- 把最具体的原话、人物、作品、动作、冲突或后果放在前半句，不要从“本期切片讲述了”开始。
- 主播标签只出现一次，并按当前账号惯例固定放在最前：`【中文名English】完整叙事句`。`【】` 中只能写主播身份，不能写爆点概括；正文仍需以具体人物、动作、冲突或后果作为钩子。
- 允许一句准确原话、一个 emoji、反问、省略号或短促感叹，但不能靠堆标点补救弱内容。
- 标题可以较长，但每个分句必须提供起因、升级、反转或后果。
- 不能改变因果、把普通动作写成没有依据的露骨行为、把主播点评写成客观事实，或移除关键限定。

结构示例：

- 【灰泽满Hazel】灰泽满刚说谁下播谁孙子，两分钟后她却先道歉跑路！
- 【灰泽满Hazel】灰泽满刚说现在没人知道这件事，结果她当场说漏嘴！
- 【灰泽满Hazel】灰泽满宣战《具体歌曲》，结果直播间当场争起谁才是第一歌势！
- 【灰泽满Hazel】灰泽满刚说这有什么难的，三分钟后她却决定放弃！

### cover_mode：三选一

- `quote-impact`：人物表情占一侧，另一侧放一条超大原话或判断。
- `evidence-reaction`：保留原始 SC、弹幕、聊天、动态或画面证据，旁边放主播反应；证据文字不能让生成模型重写。
- `clash-challenge`：两个人、两首歌、两个说法或预期与结果左右对立。

### cover_text：上下两个区域

- `cover_text_primary` 是必填上区，放具体原话、带对象的问题或异常处境。
- `cover_text_secondary` 是必填下区，补人物动作、后果、回应或反转。
- 每区 3–22 个有效字，可手动换一行；未换行时渲染器自动均衡为最多两行。
- 两区文字都必须留在居中 4:3 安全区内，同时兼容 4:3 裁切和 16:9 完整画面；不得把完整标题缩小塞入画面。
- 主字默认黄或白、近黑粗描边；只把反转、警告或结果强调为红色。
- 人物表情或证据占约半幅，文字占约半幅；禁止人物缩成角落、每区超过两行、纯黑背景或无意义装饰。
- 封面与标题分工：标题讲完整小故事，封面只放最尖锐的一击，二者不能逐字重复。
- 工作台自动生成的电台封面保持同一模板抽帧，但把上下文案中心移到 4:3 安全区内的右侧信息区；不得让文字覆盖左侧完整主播画面。

### 强制校验

- 所有文案禁止英文单引号，避免 FFmpeg 参数解析失败。
- 三套组合必须采用不同叙事角度和封面模式，不能只替换同义词。
- 主播标签拼写正确且只出现一次；`Hazel`、`Sumire`、`Viridis` 等英文名不得串用。
- 证据型封面必须保留原始截图文字，不得生成伪造弹幕、SC 或聊天。
- 在实际信息流尺寸预览封面；主字无法一眼读清、人物表情不明显或证据不可辨认都必须重做。
